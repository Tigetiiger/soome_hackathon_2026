# Product panel — visual design critique and implementation plan (r1)

Reviewed 2026-11-06 against `sites/product/index.html`, `sites/design/DESIGN_SYSTEM.md` (v2 utilitarian) and `sites/design/theme.css`. Screenshots: `sites/reviews/r1c_prod_<view>_<1280|400>_<light|dark>.png`, views `overview trace causes fullness inbox devices integration method`. Measured values come from a Playwright pass at 1280 (`scratchpad/pw/measure_r1.js`).

The direction (navy chrome, one action blue, flat surfaces, 3 px radii, hairlines, dense) is clearly there and the content is excellent. What keeps it from feeling like a finished SMART module is **execution consistency**: chart text that ranges from 6.5 px to 14.5 px, a top bar that wraps, repeated chips, navy and blue leaking into non-chrome / non-action roles, and status conveyed by text only.

## 2. Five biggest visual problems

1. **Charts are rendered at a fixed viewBox and stretched to the card, so type and marks are random sizes.** Measured at 1280: `#strip`, `#causeBar`, `#pofChart` scale 1.32 (11 px text → 14.5 px, dots r 4.5 → 6 px); `#gapHist`, `#bandChart`, `#simChart` 0.91 (→ 10 px); `#vehChart` 0.76 (→ 8.4 px, caption unreadable); `#traceBox` mass trace 0.59 (→ 6.5 px). See `r1c_prod_causes_1280_light.png` (bar hatch 10 px vs vehicle chart 8 px captions), `r1c_prod_trace_1280_light.png` (strip dots huge, mass trace tiny). This is the single biggest "amateur" tell.
2. **The chrome wraps.** The top bar is 75 px (two rows) at 1280 and seven rows at 400 (`r1c_prod_overview_1280_light.png` top, `r1c_prod_overview_400_light.png`). A SMART top bar is one 44 px row. The side nav also stops at the viewport bottom in long pages (sticky + fixed height), leaving the navy column cut off in full-page captures.
3. **Insight cards are noisy and their colour is not meaningful.** Each card stacks kicker + up to 3 chips + scopetag + claim + number + rows + a boxed "Show the math" + a ruled footer with ink-coloured underlined links (`r1c_prod_overview_1280_light.png`). "FINDING" appears in a blue wash and in an amber wash with the same label; the KPI row repeats "OBSERVED" four times. The design system asks for a KPI strip, not tiles.
4. **State is text-only and axis edges are clipped.** Grid "Status" and pickup "Weighed status" are plain words; "WAITING" is in action blue; lifecycle steps are grey text; strip/fullness hollow markers read as filled at 1.32× (`r1c_prod_fullness_1280_light.png`); last x label "Jul 202" clipped in strip and fullness; drift table clips "0.30" (`r1c_prod_devices_1280_light.png`); negative numbers mix "−13,520" with "-72.9%" in the same cell.
5. **Off-system colour and type.** `.btn-primary` is navy (should be the one action blue), `.tagact` "DISPUTE INVOICE" is navy, T2 tier rule is navy, links are ink with a blue underline (theme.css: action-coloured text), `th` 9.9 px (< 11 px floor), heading/body scale in rem (18.4/16.8/14.4/12.8) instead of the 11/12/13/14/16/18/22 token set; chain cards break IDs mid-digit ("OP-E-0039200 32"), see `r1c_prod_trace_1280_light.png` bottom-left.

## 3. Implementation plan (visual/layout only; data, text and behaviour unchanged)

Selectors refer to `sites/product/index.html` `<style>` block (line numbers approximate) and the render functions in its `<script>`.

1. **Size every SVG to its container (fixes the 6.5–14.5 px spread).** JS helper line ~777: change `const cw = w => NARROW() ? 560 : w;` to `const cw = (w, el) => { const c = el && el.clientWidth; return c ? Math.max(320, Math.round(c)) : (NARROW() ? 560 : w); };` and pass the container in each call: `cw(640, $("#gapHist"))`, `cw(760, $("#strip"))`, `cw(640, $("#bandChart"))`, `cw(760, $("#causeBar"))`, `cw(760, $("#vehChart"))`, `cw(760, $("#pofChart"))`, `cw(640, $("#simChart"))`, and the mass-trace chart in `massTrace()` (`cw(640, $("#traceBox"))`). Add one debounced resize handler: `addEventListener("resize", debounce(() => route(), 150))` (route already re-renders the active panel). Delete the `@media (max-width:699px){svg.chart{min-width:560px}}` rule. **Accept:** at 1280 every `svg.chart` has `getBoundingClientRect().width / viewBox.width` between 0.98 and 1.02; 11 px labels measure 11 px in all eight charts; no horizontal scroll inside any `figure` at 400.
2. **Chart text scale.** With step 1 in place, set one scale in the SVG code: axis tick labels `font-size="11"`, axis titles and annotations `11`, in-chart value labels (`.lbl-h`) `12`, nothing below 10.5. Replace the `10.5` band labels in `renderFleetCharts` with `11`. **Accept:** grep of `font-size="` inside `<script>` yields only 11 and 12 (and 10.5 nowhere).
3. **Last x-axis label clipping.** In `renderTrace` strip and `renderPof`: change right margin `R = 12` → `R = 36`, or give the last date label `text-anchor="end"` (`k === arr.length - 1 ? "end" : "middle"`). **Accept:** "Jul 2026" fully visible in `#strip` and `#pofChart` at 1280 and 400.
4. **Marks: fixed sizes and a readable hollow state.** Strip (`renderTrace`): normal dot `r=3.5`, selected `r=6`, outside-band hollow `r=4 fill=var(--surface) stroke-width=2`; band bar `stroke-width=4`. Fullness (`renderPof`): needed `r=3.5` filled; not-needed `r=4.5 fill=var(--surface) stroke-width=1.75`; the kg squares 4 × 4 stay. Add a legend under `#pofChart` using the existing `.legend` markup: filled dot "lift, needed", hollow dot "lift, labelled not needed", grey line "daily max fill", dashed line "40 % fill". **Accept:** at 1:1 scale a hollow marker shows ≥ 2 px of surface inside the ring; legend present (design rule: a legend for ≥ 2 series).
5. **Cause bar: one order and lightness = rank.** In `renderCauses`, build `const ranked = CZ.slice().sort((a,b)=>share[b[0]]-share[a[0]])` once and use it for the bar, the `<defs>` patterns and the list. Pattern tile stays 8 px (now 1:1 after step 1); hatch stroke `rgba(255,255,255,.45)` 1 px. Segment label: `x = x0 + 4`, `y = 60`, `font-size="12"`. **Accept:** bar segments left→right are the same order as the list below; no `#214269` inside any chart.
